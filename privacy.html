Data practices

Privacy policy

This policy describes the private, owner-operated Hermes Plex integration and its separate public documentation website.

Who uses this integration

The integration is configured for its account owner. It is not offered for public registration, and it has no public account database. The project maintainer can be contacted through the documentation repository. Public issues must not include private messages, event details, passwords or credentials.

Google data accessed and why

  • Gmail: read-only access can retrieve message headers, senders, recipients, subjects, dates, snippets and message content when needed for the owner’s requested review. It is used to identify commitments, deadlines and items requiring attention, not to send, delete, archive or relabel email.
  • Calendar: calendar and event information can be read to review commitments and prepare reminders. Event creation or changes on owned calendars are limited to the owner’s instructions. A broad technical permission does not authorize autonomous deletion, guest invitations or unrelated rescheduling.
  • Account and authorization metadata: the integration verifies the selected account and granted permissions and uses OAuth credentials to maintain authorized access.

Processing and selected service providers

Selected information may be processed in the private assistant, its local files and conversation history to fulfill the owner’s requests. Owner-selected task or project information may be stored in the owner’s Notion workspace or private notes. Selected content may be sent to configured AI providers for requested analysis or summarization; it must not be represented as exclusively offline processing.

Only service providers and account settings compatible with the permitted use of Google data are authorized for this integration. Google data must not be sold, used for advertising, or used to train generally available AI models. The owner is responsible for configuring provider data controls before enabling content-processing workflows.

Use of Google user data is limited to the purposes disclosed here and must comply with the Google API Services User Data Policy, including its Limited Use requirements. This documentation does not independently certify a provider’s configuration or guarantee regulatory compliance.

Storage, retention and security

OAuth credentials are kept in protected private files on owner-controlled systems, not in this public website or repository. Selected summaries, tasks, notes, conversation records and backups may persist until the owner removes them. There is no promised automatic deletion period; deletion from an active file does not necessarily remove historical backups.

The owner can remove local records and credentials, manage connected private tools, and revoke access. Private Google content is not intentionally published to these documentation pages. No system can guarantee absolute security.

Access controls and revocation

The owner can revoke the integration in Google Account connections. Revocation stops future authorized API access but does not automatically erase previously saved notes or backups; those must be managed separately by the owner. Provider and integration settings can also be changed or the assistant stopped.

This public website

These pages have no analytics scripts, advertising, forms, application cookies or Google OAuth callback endpoint. GitHub Pages hosts the public files and may log request metadata, including visitor IP addresses, for security and service operation. See the GitHub privacy statement. Following a link to Google, GitHub or another service is subject to that service’s practices.

Policy changes

The owner may update this policy when the actual integration changes. Material changes to Google-data handling require a matching disclosure and any necessary authorization before enabling the new workflow. The date below identifies this version.
